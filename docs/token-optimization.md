# Token Usage Optimization in Debate Hall

## Overview

This document describes token optimization strategies for multi-agent debates in the Debate Hall MCP server.

## Token Tracking

### Turn-Level Token Metadata

Each turn can now include optional token usage metadata:

- `token_input`: Input tokens consumed by the agent
- `token_output`: Output tokens generated by the agent
- `token_total`: Total tokens used for the turn

These fields are:
- **Optional**: Not required for backward compatibility
- **Excluded from hash chain**: Do not affect cryptographic integrity
- **Persisted**: Saved with debate state for analysis

### Usage Example

```python
# Record a turn with token usage data
result = await client.call_tool(
    "add_turn",
    {
        "thread_id": "2026-01-10-example",
        "role": "Wind",
        "content": "TURN::Exploring possibilities...",
        "token_input": 1500,
        "token_output": 500,
        "token_total": 2000
    }
)
```

## Context Window Optimization

### Sliding Window View

The `get_debate` tool supports a `context_lines` parameter to limit transcript size:

```python
# Get only the last 5 turns
status = await client.call_tool(
    "get_debate",
    {
        "thread_id": "2026-01-10-example",
        "include_transcript": True,
        "context_lines": 5
    }
)
```

### Key Features

1. **Full Storage Preservation**: Complete turn history is always maintained
2. **View-Layer Projection**: `context_lines` only affects what is returned
3. **Omission Indicator**: System message shows how many turns were omitted
4. **Hash Chain Integrity**: Full chain remains verifiable in storage

### Example Output

When turns are omitted, the transcript includes a system message:

```
[System]: [... 12 earlier turns omitted for context window optimization ...]
```

## Architectural Constraints

### What's Allowed

✅ **View-layer optimization**: Limiting returned transcript via `context_lines`
✅ **Client-side compression**: Agents using OCTAVE skills for semantic density
✅ **Count-based limits**: Using `max_turns` and `max_rounds`
✅ **Token tracking**: Recording usage metadata for analysis

### What's Prohibited

❌ **Server-side content modification**: Cannot alter turn content
❌ **Storage deletion**: Cannot remove turns from persistent state
❌ **Hash chain breaks**: Cannot compromise cryptographic integrity
❌ **Model-specific tokenizers**: Server remains model-agnostic

## RACI Dialogue Mode

### Concept

Transform debate hall from full deliberation into lightweight governance communication:

- **Responsible (R)** = Wind (Proposes action/decision)
- **Accountable (A)** = Door (Ratifies and closes)
- **Consulted (C)** = Wall (Validates constraints)
- **Informed (I)** = Observer (Receives transcript)

### Zero-Friction Yield

In RACI mode, if the Consulted (Wall) role has no objections:

```
TURN::Wall[ETHOS]::YIELD→proceed
```

This creates a "fast-path" approval without lengthy analysis.

## Token Efficiency Analysis

### Multi-Model Debate Example

Based on testing with:
- **Wind (Ideator)**: Gemini 2.0 Flash
- **Wall (Validator)**: Gemini 3 Pro Preview
- **Door (Synthesizer)**: Gemini 3 Pro Preview

#### Observed Token Usage

| Role | Input | Prompt | Total | Cached |
|------|-------|--------|-------|--------|
| Wind | 20,340 | 36,408 | 38,260 | 16,068 |
| Wall | 29,039 | 61,456 | 64,257 | 32,417 |

### Optimization Opportunities

1. **Caching**: 42-50% token savings through context caching
2. **OCTAVE Format**: Structured notation reduces verbosity
3. **Context Windows**: Limit visible history without losing integrity
4. **Yield Mechanisms**: Fast-path for uncontested decisions

## Best Practices

### For Debate Coordinators

1. Use `context_lines` for long debates (>10 turns)
2. Record token usage for efficiency analysis
3. Consider RACI mode for routine decisions
4. Enable OCTAVE preamble for token efficiency

### For Agent Implementations

1. Track and report token usage when available
2. Use compressed OCTAVE format for turns
3. Implement yield logic for uncontested Wall turns
4. Cache context when supported by model
